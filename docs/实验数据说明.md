# 实验数据说明

当前统一入口 `run.sh` 使用 `<mode>_summary_<timestamp>.txt`、
`<timestamp>_<suite>_<test>.sim.log` 保存新记录，失败列表仍为 `failed_tests_<timestamp>.txt`。
以下旧名称和输出示例用于说明已有历史实验记录；新格式详见 [RTL 测试入口](../rtl/README.md)。

## 一、测试结果数据格式

### 1.1 仿真输出格式

测试平台（`testbench.v`）在检测到 `tohost` 写入时输出以下信息：

```
[BP] branches=<N> mispredict=<N> target_miss=<N> accuracy=<X.XX>%
*** TEST PASSED ***   (或 *** TEST FAILED *** (tohost = <N>))
[PERF] mcycle=<N> minstret=<N> cpi=<X.XXXX>
```

#### 字段说明

| 字段 | 类型 | 含义 |
|------|------|------|
| `branches` | 整数 | 执行的分支指令总数 |
| `mispredict` | 整数 | 方向误预测次数（方向预测错误 + 目标地址缺失）|
| `target_miss` | 整数 | 目标地址缺失次数（预测跳转且实际跳转，但目标地址不匹配）|
| `accuracy` | 百分比 | 方向预测准确率 = (1 - mispredict/branches) × 100% |
| `mcycle` | 整数 | 总时钟周期数（来自 CSR mcycle 寄存器）|
| `minstret` | 整数 | 退休指令总数（来自 CSR minstret 寄存器）|
| `cpi` | 浮点数 | 每指令周期数 = mcycle / minstret |

### 1.2 测试结果目录

批量测试的结果保存在 `rtl/test_results/` 目录下：

```
rtl/test_results/
├── summary_YYYYMMDD_HHMMSS.txt           # 汇总报告
├── failed_tests_YYYYMMDD_HHMMSS.txt      # 失败测试列表
├── rv32ui-p-add.log                      # 单个测试日志
├── rv32ui-p-sub.log
├── rv32um-p-mul.log
└── ...
```

## 三、分支预测数据

### 3.1 数据字段详解

```
branches=4200   mispredict=168   target_miss=45   accuracy=96.00%
```

**分支总数（branches）**：在 EX 阶段执行的分支指令累计数。

**方向误预测（mispredict）**：包含两类错误之和：
1. **方向预测错误**：预测 taken 但实际 not taken，或预测 not taken 但实际 taken
2. **目标地址缺失**：预测 taken、实际也 taken，但 BTB 中缓存的目标地址与实际分支目标地址不匹配

**目标地址缺失（target_miss）**：上一条的子集，特指目标地址不匹配的情况。
- 方向预测错误时不会计入 target_miss
- 可用来评估 BTB 更新策略的时效性

**预测准确率（accuracy）**：方向预测准确率。
```
accuracy = (branches - mispredict) / branches × 100%
```

### 3.2 BP 统计的精度

- 所有计数器为 32 位无符号整数（最大计数 2^32 - 1）
- 准确率保留两位小数（如 96.00%）
- 当分支总数为 0 时，准确率显示为 N/A

### 3.3 分支预测性能期望

| 测试类型 | 预期准确率 | 说明 |
|---------|-----------|------|
| rv32ui-p-* (简单指令测试) | 85-100% | 循环结构为主，预测性好 |
| rv32um-p-* (乘除测试) | 85-100% | 循环结构为主 |
| CoreMark | 90-98% | 含复杂控制流 |
| bp_* (分支模式测试) | 依赖模式 | 用于验证特定预测行为 |

## 四、性能数据

### 4.1 CPI 数据

CPI（Cycles Per Instruction）是核心性能指标：

```
CPI = mcycle / minstret
```

**理想值**：1.0（每周期退休一条指令）
**实际值通常受以下因素影响**：

| 因素 | 对 CPI 的影响 | 说明 |
|------|-------------|------|
| Load-Use 冒险 | +0.05 ~ +0.10 | 加载后紧跟使用，插入 1 个 stall |
| 分支预测错误 | +0.05 ~ +0.20 | 每次错误惩罚 2 个周期 |
| 乘法指令 | +0.01 ~ +0.05 | 3 周期 stall |
| 除法指令 | +0.01 ~ +0.10 | 32 周期 stall（较少出现）|
| 存储器 stall | +0.00 ~ +0.05 | 访存冲突 |

### 4.2 CoreMark 数据

CoreMark 基准测试输出格式：

```
[CoreMark] Estimated Iterations/Sec: 40.500 (@50000000 Hz)
[CoreMark] Estimated CoreMark/MHz  : 0.810
```

**CoreMark/MHz** 计算公式：
```
CoreMark/MHz = iterations × 1,000,000 / mcycle
```

**Iterations/Sec** 计算公式：
```
Iterations/Sec = iterations × clock_freq / mcycle
```

### 4.3 性能基线

| 指标 | 参考值 | 说明 |
|------|-------|------|
| rv32ui-p-* 平均 CPI | 1.15 - 1.30 | 简单指令测试 |
| rv32um-p-* 平均 CPI | 1.30 - 1.60 | 含乘除指令测试 |
| CoreMark CPI | 1.20 - 1.50 | 基准测试 |
| CoreMark/MHz @1 iter | 0.6 - 1.0 | 取决于分支预测效果 |

## 五、测试执行数据

### 5.1 超时检测

测试平台设置默认超时 400,000 ns（400 μs），可通过 `+timeout_ns=<N>` 覆盖。
仿真卡住检测：如果 PC 连续 50,000,000 周期不变，自动终止。

### 5.2 测试结果判定

```
tohost 值       判定
─────────      ──────
       1       TEST PASSED  ✓
  ≠ 1 (非零)   TEST FAILED  ✗
       0       超时 / 未完成
       X       未知信号值
```

### 5.3 测试覆盖率（预期）

| 测试套件 | 预期通过数 | 预期失败 | 说明 |
|---------|-----------|---------|------|
| rv32ui-p-*（40 个） | 39-40 | 0-1 (fence_i) | fence.i 为可选实现 |
| rv32um-p-*（8 个） | 8 | 0 | 乘除指令 |
| UART 测试（6 个） | 6 | 0 | 收发/回环/溢出 |
| 分支预测测试 | 全部 | 0 | 模式验证 |

```csv

```

  Run 3: CPI=1.2410, CoreMark/MHz=0.806
