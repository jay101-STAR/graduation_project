## 一、环境要求

### 1.1 必需工具

| 工具 | 版本要求 | 用途 |
|------|---------|------|
| **Synopsys VCS** | 2020+ | RTL 仿真编译与运行 |

## 二、快速上手

统一入口为 `./run.sh`，完整子命令、参数和日志说明见 [RTL 测试入口](../rtl/README.md)。
旧的独立运行脚本已合并；测试命令会恢复原始内存镜像，`prepare` 成功后保留新镜像。

### 2.1 编译仿真可执行文件

所有命令在 `rtl/` 目录下执行：

```bash
cd rtl/
make simv_build
```

编译成功后将生成 `simv` 可执行文件。

### 2.2 运行单个 ISA 测试

```bash
# 运行 rv32ui-p-add 测试
./run.sh single rv32ui-p-add

# 运行 rv32um-p-mul 测试（乘法指令测试）
./run.sh single rv32um-p-mul
```

### 2.3 运行全部回归测试

```bash
# 完整回归（编译 + UART 测试 + ISA 批量测试）
./run.sh all

# 跳过 fence.i 测试（fence.i 通常未完全实现）
./run.sh all --skip-fencei

# 跳过编译步骤（已有 simv）
./run.sh all --no-build
```

### 2.4 运行分支预测测试

```bash
# 运行分支预测模式测试
./run.sh bp

# 强制重新编译后运行
./run.sh bp --build
```

### 2.5 运行 CoreMark 基准测试

```bash
# 运行 CoreMark（1 次迭代）
./run.sh coremark

# 运行 CoreMark（10 次迭代）
./run.sh coremark 10
```

### 2.6 运行 UART 外设测试

```bash
# 运行 UART 烟雾测试
./run.sh uart
```

## 三、详细操作指南

### 3.1 编译流程

```
┌─────────────┐
│  修改 RTL   │
└──────┬──────┘
       ▼
┌─────────────┐
│ make clean  │  (可选，清理旧编译产物)
└──────┬──────┘
       ▼
┌─────────────┐
│make simv_build│  (编译 RTL → simv)
└──────┬──────┘
       ▼
┌─────────────┐
│  运行测试   │
└─────────────┘
```

Makefile 中的编译命令：

```bash
# VCS 编译
vcs -full64 -sverilog -timescale=1ns/1ns \
    +v2k +define+fsdb \
    -debug_acc+dmptf -debug_region+cell+encrypt \
    -cpp g++-4.8 -cc gcc-4.8 \
    -debug_access+r -kdb -lca \
    +lint=TFIPC-L \
    $(SRCS)
```

### 3.2 单测试运行流程

`run.sh single` 的内部流程：

```
1. 定位测试 ELF 文件（在 verification/riscv-tests/isa/ 下）
2. 备份当前 instrom.hex 及 Bank HEX/COE/MEM
3. 将 ELF 转换为 HEX（objcopy + od）
4. 初始化指令存储器 Bank（mem_image_tool.py init-instrom）
5. 加载数据段（mem_image_tool.py overlay-data）
6. 生成存储器辅助文件（mem_image_tool.py emit）
7. 运行 simv 仿真
8. 恢复全部原始内存镜像（失败或中断也恢复）
```

### 3.3 批量测试运行流程

`run.sh isa` 的内部流程：

```
1. 搜索匹配的测试文件（默认：rv32ui-p-* + rv32um-p-*）
2. 备份当前存储器映像
3. 对每个测试文件：
   a. ELF → HEX 转换
   b. 替换 instrom.hex + 更新 Bank
   c. 运行 simv（10 秒超时）
   d. 解析 [BP]、[PERF]、PASS/FAIL
4. 恢复原始存储器映像
5. 输出汇总报告
```

### 3.4 CoreMark 基准测试流程

`run.sh coremark` 的内部流程：

```
1. 使用 riscv32-unknown-elf-gcc 编译 CoreMark 源码
   - 指令集：-march=rv32im_zicsr -mabi=ilp32
   - 优化级别：-O2 -ffreestanding -nostdlib
2. 生成内存映像（统一 ELF 转换 + mem_image_tool.py）
3. 检查/编译 simv（运行前自动检查源码时间）
4. 运行仿真
5. 校验 CRC、性能窗口、停顿统计，并估算短迭代 iterations/MHz
6. 恢复全部原始内存镜像
```

### 3.5 使用默认汇编测试

```bash
# Makefile 中的默认编译与运行
make comp
```

这会编译 `rtl/vsrc/instrom/bp_tests/bp_tntn.s` 为默认测试程序。

## 四、测试执行指引

### 4.1 修改 RTL 后的标准测试流程

```bash
# 第1步：运行单个相关测试验证改动
./run.sh single rv32ui-p-add

# 第2步：运行子系统回归
# 如果改动了分支预测：
./run.sh bp

# 如果改动了 UART：
./run.sh uart

# 第3步：运行完整回归
./run.sh all --skip-fencei
```

### 4.2 测试参数和选项

| 参数 | 用途 | 示例 |
|------|------|------|
| `+uart_tx_print` | 在 sim.log 中打印 UART TX 数据 | `./simv +uart_tx_print` |
| `+uart_rx_smoke` | 串行注入一个字节 0x41 | `./simv +uart_rx_smoke` |
| `+uart_tx_smoke` | TX 烟雾测试模式 | `./simv +uart_tx_smoke` |
| `+uart_loopback_smoke` | 回环测试模式 | `./simv +uart_loopback_smoke` |
| `+uart_rx_overrun_smoke` | RX 溢出测试（注入 5 字节） | `./simv +uart_rx_overrun_smoke` |
| `+debug_m_ext` | 打印 MUL/DIV 扩展调试信息 | `./simv +debug_m_ext` |
| `+timeout_ns=<N>` | 设置超时时间（纳秒） | `./simv +timeout_ns=1000000` |

### 5.2 关键调试信号

| 信号路径 | 说明 |
|---------|------|
| `top.u_core.pc_if_pc` | IF 阶段程序计数器 |
| `top.u_core.if_instruction` | 当前取到的指令 |
| `top.u_core.id_ex_pc` | EX 阶段 PC |
| `top.u_core.ex_reg_rd_data` | EX 阶段计算结果 |
| `top.u_core.wb_reg_rd_wen` | WB 阶段写使能 |
| `top.u_core.ex_pc_pc_wen` | PC 重定向事件 |
| `top.u_core.ex_mul_busy` | 乘法器忙信号 |
| `top.u_core.ex_div_done` | 除法器完成信号 |
| `tohost_value_register` | 测试结果（1 = PASS） |
| `tohost_value_dataram` | 数据段 tohost 值 |

## 六、故障排除

### 6.1 常见问题

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| `vcs: command not found` | VCS 未安装或 PATH 未配置 | 确认 VCS 安装并设置 PATH |
| `riscv32-unknown-elf-objcopy: not found` | 工具链未安装 | 安装 riscv-gnu-toolchain |
| `TEST FAILED` (tohost ≠ 1) | RTL 行为异常 | 查看 sim.log，使用波形调试 |
| `TIMEOUT` | 测试卡死 | 检查是否修改了流水线控制逻辑 |
| `fence_i` 测试失败 | fence.i 未完全实现 | 使用 `--skip-fencei` 跳过 |
| `make: vcs: Command not found` | 同上 VCS 问题 | 使用完整路径或配置 PATH |
| 仿真异常缓慢 | 波形 dump 开启 | 注释 testbench.v 中的 fsdbDumpfile |

### 6.2 查看日志

```bash
# 查看仿真输出（在 rtl/ 目录下）
cat sim.log

# 查看测试结果目录
ls test_results/

# 查看具体测试日志
cat test_results/*_isa_rv32ui-p-add.sim.log
```

### 6.3 清理构建

```bash
# 清理所有生成文件
make clean
```

**注意**：`make clean` 会删除所有仿真产物，包括 test_results 目录。

### 7.2 CoreMark 结果解读

运行 `./run.sh coremark` 后，输出示例：

```
[PERF] mcycle=1234567 minstret=987654 cpi=1.2500
[BP] branches=12345 mispredict=123 target_miss=45 accuracy=99.00%
Short-run region Iterations/Sec: 40.500 (@50000000 Hz)
Short-run region iterations/MHz: 0.810
```

- **mcycle**：总时钟周期数
- **minstret**：退休指令总数
- **cpi**：每指令时钟周期数（mcycle / minstret）
- **iterations/MHz**：短迭代性能估计；正式 CoreMark 得分还需满足至少 10 秒运行要求
- **Iterations/Sec**：每秒迭代次数
